# 全部来源的独立加载

“全部来源”是来源筛选中的可选项；启动默认仍为豆包直播，左侧导航保持现状。

页面分别请求 `/api/v2/feed?source=doubao` 和 `source=kafei`，不调用需要等待全部来源的聚合请求。每个来源单独保存页码、游标、加载状态和错误状态。谁先返回就先追加谁的卡片；未完成的来源不会阻塞其他来源继续分页。失败只影响该来源，重试沿用失败页的页码和游标。

同一来源的分页重叠会去重，两个来源的同场比赛保持独立。卡片焦点 ID 包含来源，避免两站恰好使用相同房间 ID 时发生冲突。数据追加时保留现有 DOM，不排序、不替换已有卡片；来源状态预留固定行高，避免迟到状态推动卡片。切页、切来源和切分类均取消旧请求并忽略迟到响应。

分页触发时再次检查当前滚动位置，避免处理列表增长前产生的旧可见事件而连续预加载。加载失败的来源需要手动重试，其他来源可以继续分页。重试按钮支持方向键、确认键和鼠标焦点。

## 验证（2026-10-25）

- `node --test tests/feed-pager.test.cjs`：8 项行为测试，覆盖来源时序、独立分页及游标、失败页重试、取消、去重、空页及重复游标终止、同步请求失败；已加入 Debug 与 Release CI。
- Go race tests、Go 1.23 vet、JavaScript 语法和应用结构校验。
- 真实接口浏览器验证：豆包先显示时咖啡仍在加载；实际网络请求只包含单独来源。
- 浏览器故障注入：豆包先返回 12 张卡片，咖啡后追加 12 张；已有焦点仍是同一个 DOM 元素，卡片坐标和滚动距离一致。
- 分页故障注入：豆包第二页使用 `D2`，咖啡第二页使用 `K2`；咖啡失败后保留 35 张已有卡片，方向键和确认键只重试咖啡第二页。
- 切来源取消咖啡第三页，随后送入该请求的迟到响应，未混入新来源列表。
- `960x540`、`1280x720`、`1920x1080` 三种浏览器视口均保持每行 4 张卡片，来源筛选完整；验证方向键移动和鼠标移入高亮。

以上是浏览器与共享 Go 核心验证；新增交互尚需正式 APK 在电视盒子上复测。
