# 核心服务绑定与连接恢复

## 故障与修复

设备旧版日志记录过 `Stopping service due to app idle`。原实现只通过 `startService()` 启动普通服务，`onBind()` 返回空；返回前台没有健康检查，Go 退出后也没有自动监督。界面可能仍保留旧端口，随后所有请求失败。

现在由 Activity 使用 `BIND_AUTO_CREATE` 持有绑定，从创建持续到销毁，后台切换不主动解绑。核心不再作为独立启动的后台服务运行。真正关闭应用时解绑，由 Service 销毁并清理自己拥有的 Go 子进程。

`CoreProcessSupervisor` 负责单个子进程及其 readiness。每次启动使用独立 instance 和代次；旧输出线程既不能发布旧地址，也不能在退出时清掉新地址。进程意外退出后清理 endpoint，Service 有界重试；每分钟最多安排三次自动退避重试（300/600/1200ms），手动重试可以重置预算。正常关闭不触发重启。

返回前台立即检查 `/health`，使用直连回环地址、短超时和 instance 校验；前台期间每三秒检查。健康且 instance 未变化时保留 WebView、焦点和播放器。连续健康检查失败、子进程退出或地址变化时自动接回新核心；旧健康检查不能停止新实例。检查与连接等待复用单个工作线程。

恢复前保存页面、来源、分类和焦点，以及正在观看的赛事标识和线路序号，不保存视频签名 URL。新界面重新获取线路；原本暂停时首帧后恢复暂停。直播重新连接不保证画面无间断，录像恢复尚不保存播放进度。核心仍健康但 WebView 报连接失败时只重建 WebView，保留核心与元数据缓存。界面恢复也有重试预算，避免持续失败造成重载循环。

启动等待上限 15 秒；已启动应用的连接恢复等待上限 6 秒。多次失败后显示“连接恢复失败，请按确认重试”；运行时提示为“连接中断，正在重新连接…”。后台时不执行页面重载，退出时取消任务、解绑、释放播放器和 Go 子进程。

## 验证（2026-10-25）

- Java 8 兼容编译、JUnit 8 项：并发启动去重、退出后重建、旧 ready/旧输出线程隔离、迟到健康检查隔离、正常关闭不重启、启动失败可重试、退避上限和手动重置。
- 浏览器模拟原生桥：恢复同一赛事的第二条线路；暂停状态恢复后仍暂停并移除加载遮罩；连续两次 HTTP 0 只请求一次自动恢复，显示非技术化文案。
- 浏览器恢复赛程页、“全部来源”和足球分类。
- 现有来源分页行为测试、Go race tests、JS 语法及应用结构校验。
- GitHub Debug CI 新增 Android 单测与 lint，随后构建全部 ABI 的调试 APK；正式 Release 原有单测/lint/签名流程保留。

绑定、后台切换和 Media3 的实际行为仍需发布新 APK 后在电视盒子复测；浏览器桥模拟与 JVM 假进程不等同于实机验证。Android 在内存紧张时仍可能终止应用，本修复提供绑定和恢复机制，不承诺进程永不退出。
